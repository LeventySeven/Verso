# Theme Synthesis: Model / Provider / Routing (§6.4)

**Theme keys touched by these sources:** model, evals, loop_harness, strategy, context
**Sources read (16 note files):** LLM Architecture Gallery, Machines of Loving Grace, The Bitter Lesson, Understanding Reasoning LLMs, Deep Learning Curriculum, The Big LLM Architecture Comparison, The Scaling Hypothesis, The Ultra-Scale Playbook, Crossing the Uncanny Valley of Conversational Voice, Optimizing AI Inference at Character.AI, AI Integration and Modularization, Agent Design Is Still Hard, Software 2.0, The Rise of the AI Engineer, Measuring AI Ability to Complete Long Tasks.

---

## Cross-source picture

The model/provider layer is the place where the harvest is *most* at risk of over-building, and the sources are nearly unanimous that the right move is to stay thin and treat models as interchangeable processors. Three independent lines of evidence converge:

1. **Models commoditize; value accrues to the horizontal layer above them.** Thompson (AI Integration and Modularization) states it directly — "models will certainly differ, but not in a large enough way to not be treated as commodities" and "the most value will be derived from building platforms that treat models like processors." Character.AI proves the economic corollary from the other side: the *serving system* is the moat (33x cost reduction since 2022; 13.5x cheaper than commercial APIs), not the weights. The Bitter Lesson + Scaling Hypothesis supply the philosophical floor: simple architecture aligned with scaling beats clever special-purpose design, so a model adapter that hard-codes one provider's quirks is exactly the handcrafted-structure anti-pattern at the framework layer.

2. **The interesting routing axis is reliability and tool-call quality, NOT price-per-token or model family.** Ronacher (Agent Design Is Still Hard) is the sharpest practitioner signal: "a better tool caller will do the job in fewer tokens. There are some cheaper models available than Sonnet today, but they are not necessarily cheaper in a loop." Haiku/Sonnet are "still the best tool callers" for the loop; GPT family "has not worked well for the main loop"; Gemini 2.5 for document/PDF subtask inference. This is *cross-model role assignment by empirical capability*, which is exactly Verso's role-tiered design — but it sharpens the selection *criterion*: tool-call quality, not token price, is the primary axis for the loop tier.

3. **As raw capability scales, the reliability gap WIDENS the value of the harness, including the model layer's failover.** METR's 80% time-horizon is 4–6x shorter than the 50% horizon at the same ~207-day doubling time — reliability lags capability by a large constant factor, and "models struggle with unstructured 'messy' environments." Cross-model failover (never same-model), retry tiers, and structured recovery are the mechanisms that close this gap; they get *more* valuable as models improve, not less.

A secondary, lower-priority thread: the model-internals sources (Architecture Gallery, Big LLM Comparison, Ultra-Scale Playbook, Character.AI) all converge on KV-cache as THE dominant constraint, which is primarily a §5.2 context-engineering story but has one real §6.4 consequence: **the cache/prefix invariant the framework must respect is model-attention-type-dependent** (MLA vs GQA vs MQA vs hybrid/linear), so the provider adapter must expose cache semantics rather than assume one shape.

**Net for §6.4:** almost everything resolves to *confirm* or *sharpen* the already-known design (cross-model failover; role-tiered cheap-loop/mid-retry/reasoning-synthesis). The few genuinely new items are interface notes (expose cache semantics per provider; distilled model as the reasoning-tier default) that should be locked as small interface decisions and otherwise deferred. There is no source-supported case for new routing machinery (no model-router DSL, no learned router, no automatic price optimizer) in a v1 personal-infra framework.

## Deltas (deduped, highest-value first)

### 1. Tool-call quality — not token price — is the loop-tier selection criterion [SHARPENS §6.4] — adopt-now
**Source:** Agent Design Is Still Hard (Ronacher). Verbatim: *"A better tool caller will do the job in fewer tokens. There are some cheaper models available than Sonnet today, but they are not necessarily cheaper in a loop."* Also: *"I think Haiku and Sonnet are still the best tool callers available, so they make for excellent choices in the agent loop."*
**Why it matters:** The role-tiered model architecture is already in the harvest, but the *axis* for the cheap-loop tier was implicitly "cheap = low price/token." This source contradicts that framing with field data: cheapest-per-token ≠ cheapest-per-task because a worse tool caller burns more turns. This is the single most actionable model-layer delta. Sharpen the PRD to state the loop-tier default is selected by tool-call reliability, with price/token a secondary tiebreaker.

### 2. Cross-model failover by behavioral role, not family — confirmed by an independent production team [CONFIRMS §6.4] — confirm
**Source:** Agent Design Is Still Hard (Ronacher): Haiku/Sonnet for the loop, Gemini 2.5 for document/PDF/image subtask inference, GPT "has not worked well for the main loop." 
**Why it matters:** This is direct production confirmation of the role-tiered + cross-model design already in the harvest (cheap loop / mid retry / reasoning synthesis, cross-model not same-model). Different model families are genuinely better at different *roles*, and a real team routes by role across providers. No PRD change beyond citing this as evidence; do NOT expand into a routing engine.

### 3. Model commoditization + "treat models like processors" is the explicit positioning of the model layer [CONFIRMS §6.4 / SHARPENS §4] — confirm
**Source:** AI Integration and Modularization (Thompson). Verbatim: *"Models will certainly differ, but not in a large enough way to not be treated as commodities."* and *"The most value will be derived from building platforms that treat models like processors."*
**Why it matters:** Strongest external validation of the model-agnostic provider abstraction. The developer should never need to know which model ran a loop iteration; the model interface should be as opaque and stable as a CPU interface. Confirms the bet; adopt the "models as processors" phrasing in §6.4/§4 language. Counter-note (monitor, don't act): Thompson's *data-gravity* argument means cloud incumbents may ship native agent runtimes — Verso's answer is cloud-agnostic, not cloud-native; this is a §12 GTM watch item, not a §6.4 change.

### 4. The serving layer is the moat; API-passthrough faces a hard cost ceiling [CONFIRMS §6.4 / SHARPENS §1] — confirm
**Source:** Optimizing AI Inference at Character.AI. Verbatim: *"if we were to serve our traffic using leading commercial APIs, it would cost at least 13.5X more than with our systems"*; 33x cost reduction since 2022; 95% inter-turn KV cache rate.
**Why it matters:** Concrete economic proof that weights are commodity and the harness/serving layer is where differentiation lives — confirms the core Verso bet. For §6.4 specifically: a framework that only does naive API passthrough inherits the 13.5x ceiling, which is why the *context/cache discipline* (a §5.2 concern) is the economic lever, not the model choice. No new §6.4 machinery; reinforces that the model layer's job is to stay thin and not get in the way of cache reuse.

### 5. Distilled reasoning models (32B class) are the reasoning-tier default; never use a reasoning model for the cheap loop [SHARPENS §6.4] — sharpen
**Source:** Understanding Reasoning LLMs (Raschka). Distillation > pure RL below ~32B (Llama-8B SFT-distill beat R1-Zero despite 84x fewer params; Qwen-32B pure-RL underperformed distilled variants). Reasoning models are *"more expensive to use, more verbose, and sometimes more prone to errors due to 'overthinking'"*; standard LLMs win on summarization/translation/simple-QA.
**Why it matters:** Sharpens the reasoning-synthesis tier recommendation: the synthesis tier is best served by a *distilled* reasoning model (32B class), not the largest frontier model — full 671B-class is overkill for most synthesis. And it hard-confirms the structural rule that the cheap-loop tier must NOT be a reasoning model. Lock this as a documented default; it is a config recommendation, not new code.

### 6. The provider adapter must expose cache/prefix semantics, which differ by attention type (MLA/GQA/MQA/hybrid) [NEW-IDEA §6.4 → interface] — lock-defer
**Source:** The Big LLM Architecture Comparison + LLM Architecture Gallery (MLA compresses K/V to a latent space; ablations show MLA > GQA > MHA) and Optimizing AI Inference at Character.AI (MQA = 8x KV reduction vs GQA; 1-of-6 layers global). 
**Why it matters:** The "static/dynamic prefix discipline" already in the harvest assumes a stable prefix is a stable prefix — but the cache-stability *invariant* lives at a model-specific level (latent projection for MLA; head-level for GQA; aggressive local windows for MQA/hybrid). This is the one genuinely new §6.4 implication from the model-internals sources: the provider abstraction should surface cache-point/cache-semantics as part of its interface (Anthropic's explicit cache anchors are the concrete example, via Ronacher), rather than assume one cache model across providers. Lock the interface (provider exposes cache-control), defer any per-architecture optimization — it is frontier/churny detail.

### 7. Explicit (manual) cache control beats implicit, and forces a mostly-static prefix [SHARPENS §6.4/§5.2] — sharpen
**Source:** Agent Design Is Still Hard (Ronacher). Verbatim: *"I initially found the manual management pretty dumb... But I've fully come around and now vastly prefer explicit cache management."* Three anchors (one after system prompt; two at conversation start, trailing one floats with the tail); dynamic data (current time) injected as a later message so it doesn't trash the cache.
**Why it matters:** This is a model/provider-interface design constraint, not just context engineering: the provider adapter should expose explicit cache anchors rather than hide them behind an implicit unifying layer (which is exactly what corrupted message history in his Vercel-SDK experience). Sharpen §6.4 to require the model interface to pass through provider-native cache controls; this is the mechanism that makes the §5.2 static-prefix discipline actually pay off.

### 8. Inference-time compute (long CoT, multiple samples, verification passes) is a first-class scaling dimension the loop must support without redesign [SHARPENS §6.4/§5.1] — sharpen
**Source:** The Bitter Lesson (Sutton): *"Search and learning are the two most important classes of techniques for utilizing massive amounts of computation"* — both scale arbitrarily. Cross-referenced with Understanding Reasoning LLMs (implicit inference-time scaling via longer generations) and the `<think>` tag convention.
**Why it matters:** The model layer must treat reasoning-effort / thinking-budget as a typed, model-aware parameter (some models expose explicit thinking budgets; reasoning verbosity needs capping to fight "overthinking"). Streaming long CoT and the option of multiple parallel invocations must be supported by the existing async loop without architectural change. Sharpen §6.4 to name reasoning-effort/thinking-budget as a passthrough parameter on the model interface; the loop already streams (SSE), so this is interface plumbing, not new structure.

### 9. RL-trained reasoning-model support is table stakes for the target audience, not a differentiator [CONFIRMS §6.4] — confirm
**Source:** Deep Learning Curriculum (Hilton ranks RL second only to Transformers) + The Rise of the AI Engineer (the 50M software engineers consuming APIs are the market). 
**Why it matters:** Confirms that supporting o-series / R1-style reasoning models in the provider layer is expected baseline, not an exotic add-on — but also that the *audience* (AI engineers consuming APIs, not ML researchers) wants this behind a clean interface, not exposed as training knobs. No PRD change; reinforces "stay thin, support reasoning models, don't surface training internals."

### 10. Native-int8-trained providers avoid train/serve mismatch — a model-selection criterion, not a feature [NEW-IDEA §6.4 → eval-criteria] — lock-defer
**Source:** Optimizing AI Inference at Character.AI. Verbatim: *"we natively train our models in int8 precision, eliminating the risk of training/serving mismatch."*
**Why it matters:** For a framework (not a training stack), the only actionable form is a documented provider-evaluation criterion: prefer providers whose serving precision matches training precision. This is a note in the provider-evaluation rubric, nothing to build. Lock as a criterion; defer.

## RESIST list (overkill / bullshit for a v1 personal-infra framework)

- **A model-router DSL / learned router / automatic price-optimizer.** Nothing in these sources supports it; Ronacher's lesson is the opposite — route by empirical role with a couple of static tiers. Cross-model failover + role tiers is the whole story. Building a router engine is exactly the handcrafted-structure the Bitter Lesson warns against.
- **Per-attention-architecture cache optimization (MLA vs GQA vs MQA vs linear/hybrid code paths).** These are real model-internals facts but they churn fast and are the provider's problem. Expose cache-control as an interface; do NOT implement architecture-specific tuning in the framework. (Lock interface, defer everything else.)
- **Hybrid/linear-attention-aware routing (DeltaNet + full-attention failure-mode modeling).** Frontier/emerging; flagged by the Big LLM Comparison as a future concern. No v1 design action.
- **Training-side infrastructure of any kind** (ZeRO/TP/PP/activation-recomputation from the Ultra-Scale Playbook; GRPO/RLVR/reward-model knobs from the reasoning sources). These describe how the *models Verso runs* are produced. They are background context for model-selection intuition only; building any of it into an agent harness is category error.
- **METR-style per-model P(success) calibration baked into the loop** (the logistic `p_success = σ((log h_agent − log t_task)·β_agent)`). Powerful but requires per-model calibration data the framework won't have. At most expose an optional `task_duration_estimate` / `step_budget` typed parameter and defer the calibration entirely to the eval layer; do not make the loop model-calibration-aware in v1.
- **Duplex-model / continuous-stream history support** (Sesame). Real future pressure on turn-based history, but the current ReAct loop is correctly built for today's turn-taking models. Event-sourced history (already the durable-layer choice) is the right hedge; no §6.4 action now.
- **Universal-context / "shared expert" injection as a default model-layer primitive.** The shared-expert debate (DeepSeek uses it, Qwen removed it, Llama skipped it, GLM kept it) shows no consensus — so do NOT inject universal context into every model call by default. Make it opt-in if ever; do not pre-commit.
- **A second LLM to reformat/clean model output by default** (Ronacher's output-tool experience: Gemini-2.5-Flash reformatting added latency and *degraded* quality because the sub-model lacked context). Do not build output-normalization-via-second-model into the model layer.

## Cross-source picture (AV-specific)

1. **Operators converge on "model labels not pinned versions" + fast rollback as a *reliability* requirement, not a convenience.** Crivello (Lindy, 2+ yrs production): *"You should be model maxing. You should talk to all models"*; use labels so default-model agents inherit the new default automatically; and the **"Sycophantocalypse"** (GPT-4o's abrupt sycophancy policy change silently broke agents) makes model-agnosticism *"not just a nice-to-have — it is a reliability requirement"* with **fast detection + faster rollback** as the mitigation. This is the same conclusion the PRD reaches via cross-model failover, but the *mechanism it stresses is different*: a behavioral-regression tripwire + one-flag rollback at the model layer, separate from outage/rate-limit failover.

2. **Per-step / per-micro-task model routing is how the best production pipelines actually run — and the cheap model is the default, the expensive one the exception.** Heller (CoCounsel/Thomson Reuters): *"a different model for every single prompt"* and *"Gemini 2.5 Flash — beautiful model, cheap as hell. If it works to your level of satisfaction, use that. Don't use 2.5 Pro."* Hashimoto's **Oracle pattern**: expensive slow model for plan/spec → cheap fast models for execution → expensive model again for final review. Crivello's concrete defaults: Sonnet=balanced, Flash=speed, o3=smartest. This *confirms* role-tiered models but sharpens the **default-cheap, escalate-deliberately** posture and adds the **plan/exec/review** tri-phase as a named recommended pattern.

3. **The reasoning tier is *conditional on base-model capability* — routing a weak model to a hard reasoning task is strictly worse than a direct call.** Noam Brown (o-series architect): test-time compute *"on top of GPT-2... wouldn't have gotten you almost anything"* — *"if you ask a pigeon to think really hard about playing chess, it's not going to get that far"*; and the upside where it applies is *"a model that's like a thousand to a hundred thousand times bigger."* Chung (o1): below a **threshold intelligence** the incentive/effort is wasted. This adds a real **capability-gate** to the reasoning-effort dial: `effort=high` should be gated on a model that clears the threshold, not applied blindly to the cheap loop tier.

4. **Empirical-model-selection-by-running (not by spec sheet) is the practitioner norm.** Hashimoto runs identical tasks across cloned repos with different models to pick the best; Heller's 999/1000 micro-step evals drive per-step model choice; v0 proved the **composite pipeline beats the base model by +29pp** (base Sonnet 4 = 64.71% error-free → composite = 93.87%) — *"+29 percentage points came from engineering, not from a better base model."* This is the strongest external proof of the harness-over-weights bet and it lands squarely on §6.4: the model layer's job is to be swappable so the *pipeline* can be tuned empirically.

5. **Two real contradictions the corpus surfaces (worth honest PRD framing, not resolution):**
   - **Open-weight/local-swarm optimism vs. hard production data.** Prasanna/Goose ("swarms of smaller, open models"; runs Qwen/DeepSeek/local-embedded) and Sutskever/Silver/Sutton (experience/open trajectory) pull toward many-small-open-models. **Goyal/Braintrust** counters with the only hard market number in the set: among sophisticated production teams (Stripe/Notion/Replit) **open-source in production is <5% and *declining***, cloud-partner access (Claude-via-AWS/OpenAI-via-Azure) is *"surprisingly low"*, and *"fine-tuning is a mechanism… the outcome is not fine-tuning"* — also declining. Verso's model-agnostic abstraction is the correct hedge for *both* futures; the PRD should not bet the default config on open/local models, but must keep the seam open.
   - **Data-wall: Sutskever/Silver ("high-quality data nearly exhausted") vs. Mark Chen ("compute today is the answer; pre-training is a muscle that needs exercising; we're not at a data wall").** Both are 2025/2026 frontier voices. Implication for §6.4 is only: don't hard-code an assumption that models stop improving (keep failover chains and tiers config-driven so a capability jump is a config change, not a redesign).

## Deltas (AV-only, deduped against WF1 synthesis + PRD §6.4 + ALREADY-KNOWN; highest-value first)

### A1. Behavioral-regression tripwire + one-flag model rollback (distinct from outage/rate-limit failover) [SHARPENS §6.4] — sharpen
**Source:** Living-Lindy / Flo Crivello. *"Sycophantocalypse"*; model-agnosticism is *"a reliability requirement"*; mitigation = *"fast detection + faster rollback."* Model labels not pinned versions (default-model agents auto-inherit the new default).
**New vs. PRD:** PRD §6.4 failover triggers are *outage / rate-limit / malformed-tool-call*. A silent **behavioral** regression (provider ships a new snapshot behind the same label and tone/policy shifts) passes all three and still breaks agents. Add: (a) the model layer should support **pinned-snapshot vs. floating-label** as an explicit choice, and (b) a rollback path is the eval layer's regression signal flipping a config flag — *not* new loop machinery. One sentence + a config field, not a subsystem.

### A2. Reasoning-effort must be capability-gated (don't spend `effort=high` on a sub-threshold model) [SHARPENS §6.4/§5.1] — sharpen
**Source:** Noam Brown (capability threshold; 1,000–100,000× substitution only above it; "pigeon… chess"); Chung ("threshold intelligence"). Both `read_partial` (Latent Space paywalled; Chung slides image-only) but the threshold claim is consistent across both + the Raschka notes.
**New vs. PRD:** PRD has a free-standing `effort="low|medium|high"` dial. The AV evidence says effort is *only* meaningful above a base-capability threshold — applying it to the cheap `loop_model` wastes tokens/latency for *worse* results. Sharpen the dial doc: high-effort routes to the reasoning-capable tier; the cheap loop tier ignores/floors it. Pure doc + routing-default, no code.

### A3. Cross-model failover changes the **tokenizer**, not just capability — carry tokenizer family + quirks in the provider profile [NEW-IDEA §6.4 → interface] — lock-defer
**Source:** Karpathy "Let's Build the GPT Tokenizer." SolidGoldMagikarp class (vocab token with no LM embedding → incoherent output); `<|endoftext|>` injection breaks the model entirely; tiktoken (byte-BPE) vs SentencePiece differ in vocab/merge/special-tokens; YAML << JSON in tokens.
**New vs. PRD/WF1:** WF1 §6.4 delta #6 covers exposing **cache/prefix** semantics per attention type — it does **not** cover **tokenizer**-level differences across a failover hop. A prompt tuned on one tokenizer can hit vocab-gap / special-token failures on the fallback. Add to `ProviderProfile`: tokenizer family + a known-quirks slot, and a **special-token sanitization** pass on untrusted tool/web content before it reaches *any* model (this also lands as a §6.3 safety item — strip `<|endoftext|>`-class tokens). Lock the interface field + the one-function sanitizer; defer per-tokenizer optimization.

### A4. muP width-invariance ⇒ actively RESIST per-model harness branches; reuse primary's sampling params on the fallback [CONFIRMS §6.4 + hardens RESIST] — resist
**Source:** Greg Yang, "Unreasonable Effectiveness of Mathematics" (muP: *"narrow and wide neural networks share the same set of optimal hyperparameters"*; muTransfer adopted in GPT-class training). `read_partial` (no transcript; speaker's own abstract + TP5 paper).
**New vs. PRD:** Gives a *first-principles* reason for the existing thin-provider stance: since optimal HPs transfer across model scale (and frontier models train muP-style), the framework should **not** maintain per-model loop variants, and a fallback model should **default to the primary's temperature/top-p** rather than re-tuning. This isn't a new feature — it's a justification that *strengthens* the WF1 RESIST against per-architecture code paths. Add as a one-line rationale + a sane default (inherit sampling on failover).

### A5. Eval the **exact deployment artifact**; warn when prod model ≠ eval model [SHARPENS §6.4/§5.5] — sharpen
**Source:** Bubeck, "Sparks of AGI" — public GPT-4 was *"slightly dumbed down"* from the internal eval version. Reinforced by Crivello's snapshot-drift point and Hassabis ("predict core metrics… doesn't translate to MMLU/math" — capability emergence is not predictable from proxies).
**New vs. PRD:** The PRD eval section shares the run path (eval == run) but doesn't assert **artifact identity**. Add: the model interface must record the exact provider+snapshot used; the eval harness warns/fails if the production model id differs from the evaluated one (quantization, routing, or silent version drift all trip it). Metadata + a guard, not machinery.

### A6. SSM / hybrid (constant-time, fixed-state) backends break the transformer KV-cache cost model that compaction assumes [NEW-IDEA §6.4 → future interface] — lock-defer
**Source:** Cartesia / Albert Gu & Karan Goel (No Priors). *"time to process any new token is basically constant for a recurrent model… for a transformer it scales with history"*; ~10:1 SSM:attention hybrids; "fuzzy compression" loses exact recall. Mamba-3 "inference-first."
**New vs. PRD/WF1:** WF1 framed cache as MLA/GQA/MQA *attention* variants — all still transformer KV-cache. SSM/hybrid backends have **no growing KV cache at all**, so observation-masking compaction (N=10) is solving a cost that doesn't exist there (and exact-recall tasks need the 1 attention layer / external retrieval). The provider profile should carry a **cache-growth model** ("kv-quadratic | fixed-state | hybrid") so compaction can be a no-op when the backend is fixed-state. Lock the descriptor field; build nothing now (no production SSM API the target audience uses yet).

### A7. Distilled-teacher variant as the worker/fast tier (same architecture, fewer steps) — superset of "smaller base model" [SHARPENS §6.4] — sharpen
**Source:** FLUX / Rombach — one full teacher ([pro]) → guidance-distilled [dev] → LADD [schnell] (1–4 steps). v0/d0 corroborates with a **quick-edit model + speculative decoding** (8,130 chars/sec, 10–40× faster) as the worker tier alongside the frontier generator.
**New vs. WF1:** WF1 delta #5 already says "distilled 32B reasoning model is the *reasoning-tier* default." This is the inverse and additive: for the **cheap worker/fast-edit tier**, prefer a **distilled/quick-edit variant of the same family + speculative decoding** over a fundamentally different small model — better behavioral consistency across the tier boundary. Config recommendation in the role-tier doc; no new code.

### A8. Provider-agnosticism belongs at the **call site (identical signatures)**, explicitly *not* runtime routing — bounds the abstraction [CONFIRMS §6.4] — confirm
**Source:** Ubl/Vercel AI SDK — provider-agnostic via *identical function signatures* across OpenAI/Anthropic/Mistral, **no opinionated orchestration**; *"JDBC for the nineties."* Aravind (commodity models, app-layer moat) and Thompson (WF1) agree.
**New vs. PRD:** Mostly confirms `ProviderProfile`, but adds a *boundary*: the right altitude for model-agnosticism is the **call signature**, and runtime *routing* should stay per-node config (which the PRD already says). Useful as the explicit "abstraction stops here" line in §6.4 / §2 non-goals. No change beyond phrasing.

### A9. Token *supply-chain* is a real ops reality at scale, but stays out of the framework [CONFIRMS §6.4 + RESIST] — resist
**Source:** Cursor/Truell — consumed *"high double-digit percent"* of a provider's revenue; *"we got very good at hunting out all the Sonnet tokens"* across resellers (AWS/GCP/Azure/Databricks/Snowflake). Prasanna runs 4 providers + local by sensitivity.
**New vs. PRD:** Confirms multi-provider `provider_order` / fallback is correct, and explicitly bounds it: **token sourcing/arbitrage is supply-chain ops, not framework code** — the framework exposes provider order + keys and stays out of reseller arbitrage. Reinforces RESIST against a "price-optimizer" router.

### A10. Hours-saved / pain-relief is the operator-grade eval signal that drives model choice [SHARPENS §5.5→§6.4] — sharpen
**Source:** Prasanna/Goose (primary metric = **manual hours saved/week**, 8–10 h/wk/engineer, 25% org target); Ubl (*"what part of your job do you hate most?"*); McGrew (reliability is the *trust contract* that makes delegation rational, not a capability score).
**New vs. PRD:** The PRD's §5.5 reliability surfacing (p50/p80 horizons) is task-level; this adds that the **model-selection** decision in practice is anchored to a workflow-level time/cost signal. One framing line in §6.4/§5.5: "the right eval to choose a model tier on is workflow time/cost saved, not benchmark accuracy." Doc only.

## RESIST list (AV-pass additions — over and above the WF1 RESIST above)

- **Per-model / per-tokenizer / per-architecture loop branches.** muP (A4) gives the first-principles reason: optimal behavior transfers across scale; the WF1 RESIST against per-attention cache code now also covers tokenizer-specific code paths — expose descriptors (A3, A6), branch nothing.
- **Defaulting the config to open-weight / local / swarm models.** Braintrust's <5%-and-declining production data (vs. Goose/Sutskever optimism) says keep the seam open but do **not** make open/local the default routing target in v1.
- **Token arbitrage / reseller-sourcing logic in the framework** (A9, Cursor). Supply-chain ops; expose provider order + keys only.
- **Continual-learning / online-weight-update hooks in the model layer.** Tworek ("continual learning is one of the last building blocks"), Sutton ("checkpoint/resume ≠ learning from experience"), Karpathy ("hippocampus gap"), Schulman ("medium-term memory neglected") all name this as the *missing capability* — i.e., it does **not** exist to integrate. The durable event log is the right hedge (it *could* feed future RFT, per Noam Brown), but building weight-update plumbing into the agent harness is category error for v1.
- **Outer planning/tree-search layer over the loop (AlphaZero-atop-LLM, Hassabis).** Genuinely interesting for a *durable* long-horizon mode, but it is a §6.1/§6.2 research idea, **not** a §6.4 model-layer change; do not let it leak into the model abstraction.
- **A "surprise/calibration" world-model eval baked into the model layer** (Sutton's "they will not be surprised"). A nice §5.5 research spike at most; not a model-routing primitive.
- **Reasoning-effort applied blindly across all tiers** (A2). Gate it; don't expose it as a global knob that the cheap loop honors.
