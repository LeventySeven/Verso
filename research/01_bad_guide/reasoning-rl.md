# Reasoning Models + RL (RLVR/GRPO)

## Understanding Reasoning LLMs (Sebastian Raschka) — https://magazine.sebastianraschka.com/p/understanding-reasoning-llms — read

- **Definition of reasoning**: "the process of answering questions that require complex, multi-step generation with intermediate steps." Reasoning models excel at puzzles, advanced math, and coding — NOT summarization, translation, or factual Q&A. Key rule: "use the right tool (or type of LLM) for the task."
- Reasoning models are more verbose, more expensive per token (explains why o1 costs more than DeepSeek-R1 at inference), and prone to "overthinking" errors.

### Four Approaches to Building Reasoning Models

**1. Inference-Time Scaling (no training required)**
- Techniques: chain-of-thought prompting ("think step by step"), majority voting (Best-of-N), beam search, Monte Carlo Tree Search (MCTS), Process Reward Models (PRM) to select best answer from a search.
- DeepSeek explicitly labeled MCTS and PRM-guided search "unsuccessful attempts" in their R1 technical report — they may still apply them at the application layer, but did not use them in R1 training.
- Cost: more expensive per query (5× more tokens → 5× cost).
- OpenAI o1 is hypothesized to lean more heavily on inference-time scaling than DeepSeek-R1, possibly with a smaller base model.

**2. Pure RL (DeepSeek-R1-Zero): RLVR without SFT**
- Base: DeepSeek-V3 671B parameters (pre-trained Dec 2024).
- "Cold start" RL — no supervised fine-tuning, RL applied exclusively.
- Reward structure:
  - Accuracy reward: LeetCode compiler for code, deterministic math parser for math.
  - Format reward: LLM judge ensures reasoning steps are in `<think>` tags.
- Emergent behavior ("Aha! moment"): The model spontaneously developed multi-step reasoning traces with no explicit training for it. The report documents the specific checkpoint where this emerged.
- Performance: demonstrates reasoning can emerge as learned behavior but is NOT top-performing; strong on reasoning benchmarks but not best-in-class.
- Key finding: RL alone proves reasoning can emerge without SFT.

**3. SFT + RL (DeepSeek-R1): the flagship approach**
- Full pipeline (6 stages):
  1. Run R1-Zero to generate cold-start SFT data (reasoning traces)
  2. SFT fine-tuning on cold-start data
  3. First RL stage: accuracy reward + format reward + consistency reward (prevents language mixing)
  4. Collect 600K CoT examples from latest checkpoint + 200K knowledge-based examples from DeepSeek-V3 base
  5. Second SFT fine-tuning on 800K combined examples
  6. Final RL stage: rule-based accuracy rewards for math/coding + human preference labels for other question types
- "Noticeable performance boost over DeepSeek-R1-Zero." The reasoning behavior comes specifically from the RLVR stages.
- This is "the key approach for building high-performance reasoning models" per Raschka.
- Standard practice: "It is actually common to include an SFT stage before RL, as seen in the standard RLHF pipeline."

**4. Pure Distillation (DeepSeek-R1-Distill): SFT only, no RL**
- NOT classical knowledge distillation. In LLM context: fine-tuning smaller models on an SFT dataset generated by larger models.
- Models trained: Llama 8B, 70B; Qwen 0.5B–32B.
- Training data: same 800K SFT dataset from DeepSeek-R1 pipeline.
- Performance: "noticeably weaker than DeepSeek-R1" but "surprisingly strong relative to DeepSeek-R1-Zero despite being orders of magnitude smaller." Performs well vs o1-mini.
- RL comparison: applying pure RL to Qwen-32B vs distillation shows "distillation is far more effective than pure RL for smaller models."
- Key insight: "RL alone may not be sufficient to induce strong reasoning abilities in models at smaller scales, whereas SFT on high-quality reasoning data can be more effective."

### RLVR vs RLHF — the core distinction

- **RLHF**: humans rank/compare multiple outputs → train a reward model (LLM) → use reward model + value model in PPO loop → 3 models in memory simultaneously (policy + reward model + value model). For 600B parameter models: 3 × 600B in memory. Very expensive.
- **RLVR**: replace the reward model with a deterministic verifier (math parser, code compiler). Replace the value model with group-relative normalization (GRPO). Net result: only 1 model in memory.
- Both use RL; the key is what provides the reward signal.

### GRPO — Group Relative Policy Optimization

- **Core innovation**: eliminates the critic (value) model from PPO entirely.
- Procedure: for each prompt, sample G outputs from the policy model → compute reward for each → normalize to get advantages: `A_i = (r_i - mean(r)) / std(r)` — i.e., how many standard deviations above/below the group mean is this completion.
- The group average acts as a proxy for what the value model would have estimated.
- Loss: policy gradient update using these advantages + KL divergence term against a reference policy (for stability).
- GRPO vs PPO: PPO learns a separate value network updated at every step; GRPO replaces that with one-shot group normalization at generation time.
- **Vanilla GRPO is "flaky"** (Raschka's word): instabilities arise every hundreds-to-thousands of steps. Community tips and tricks to stabilize:
  - Remove KL divergence term (for math tasks: helps)
  - Remove standard deviation normalization when all rewards are identical (skip the update entirely)
  - Handling multiple reward signals (accuracy + format): simple addition causes instability → GDPO (NVIDIA, 2025) improved multi-reward combination.
- Training cost: DeepSeek-V3 pre-training ~$5M; DeepSeek-R1 RL stage ~$300K (number appeared in the Nature version of the paper) — more than 10× cheaper than pre-training.
- Raschka trained a Qwen 3 model with RLVR for just 50 steps: math accuracy went from 5% → 50% on MATH-500. Interpretation: "It's not really learning new knowledge in these 50 steps. The knowledge is already there in the pre-training. This just unlocks it."

### Process Reward Models (PRM) — why they don't yet work reliably

- Outcome reward: is the final answer correct?
- Process reward: is each intermediate reasoning step correct?
- DeepSeek R1 paper listed PRM as an "unsuccessful attempt" — susceptibility to reward hacking when another model grades intermediate steps. The grader model is unreliable, which propagates through training.
- DeepSeek-Math v2 workaround: 3-model chain — (1) generating model, (2) grader of answers+steps, (3) meta-grader of the grader. Gold-level performance on math benchmarks. "Sounds excessive but performed really well." Raschka: "We will see this become standard repertoire."
- Current status: "still tricky to make work but we'll see it at some point."

### RLVR scope: math/code today, expanding

- Math and code are ideal because verification is deterministic and cheap (exact answer match, compile + run unit tests).
- Expansion examples: citations (model generates citation → another model fetches URL and checks it's the right paper), medical correctness (harder, no clean verifier).
- RLVR can use LLM-as-verifier for domains without algorithmic checkers — less robust but expands scope.
- Raschka: "We will see a lot of expansion of RLVR to new domains."

### Inference-time scaling in practice (2025/2026)

- Parallel sampling (Best-of-N): run model N times, majority vote or judge-model selects best → N× cost.
- Self-refinement: LLM writes answer → LLM critiques it → refines → repeat. Reasoning models do this internally as CoT, but you can also run an explicit outer loop.
- Recursive LM / RLMs paper (Jan 2026): LM decides how to chunk a prompt into sub-prompts, runs each recursively → "a form of inference scaling through decomposition."
- Tool calling as inference scaling: GPT-OSS benchmarks show ~1.2× performance uplift just by enabling tool calling on same model weights.
- Key Raschka observation: DeepSeek running locally feels worse than ChatGPT on the same weights because ChatGPT does pre-processing (prompt cleaning, context management) that isn't in the base model.

### Journey Learning vs Shortcut Learning

- Shortcut learning (standard SFT): train only on correct solution paths.
- Journey learning: include incorrect paths and corrections — model learns to recognize and recover from errors.
- Status: promising direction for low-budget reasoning development where RL is computationally impractical; not yet standard.

### Budget-constrained development benchmarks

- Sky-T1 (32B): 17K SFT examples, $450 total cost, "roughly on par with o1" — pure distillation.
- TinyZero (3B): <$30 to train, replicates R1-Zero's pure RL approach, shows "emergent self-verification" at tiny scale.

### Benchmark saturation / benchmaxing

- "Benchmaxing": training models specifically to score well on leaderboards without real-world improvement. Raschka alleges Llama 4 had a separate model for benchmarks.
- Leaderboards reward style over correctness (users prefer well-explained wrong answers to terse correct ones).
- Raschka: "I stopped looking at benchmark numbers. I just use the model for a few days."
- Future evaluation: agentic benchmarks — how long / how reliably can the model run to solve a complex objective — replace one-shot Q&A benchmarks.

### Architecture note (relevant to reasoning)

- Transformer still state-of-the-art in 2026; no replacement on horizon.
- MoE (Mixture of Experts): DeepSeek V3, Kimi, Mistral 3 all adopted it — "model bigger without more inference cost." DeepSeek V3.2 added sparse attention on top of MoE.
- Diffusion models for text: parallel generation is cheap but poor at sequential tasks (tool use, reasoning) because generation must be interrupted. Not replacing auto-regressive transformers at state-of-the-art.
- Pre-training: "not dead but boring" — low-hanging fruit is exhausted, better ROI in post-training.

## State of LLMs 2026: RLVR, GRPO, Inference Scaling — https://www.youtube.com/watch?v=K5WPr5dtne0 — transcribed

*Interview: Matt Turck (Firstmark) × Sebastian Raschka; 90-min conversation, 2026*

- Opening quote: "Pre-training is not dead, but pre-training is boring. It's not where the low-hanging fruit is anymore. Improvement is not so much coming from the architecture anymore. It is basically the post-training. One of the biggest drivers this year has been inference scaling. It goes from 5% accuracy to 50% by only doing 50 reinforcement learning steps. There's no one thing that fixes it all. It's a lot of little tips and tricks all over the place. If you add them up, that will give you the progress, but there's no magic bullet that gives you everything."

### Architecture in 2026

- Transformer is 8–9 years old (2017 paper) and still state-of-the-art. "If I were to build a state-of-the-art model today, it would still be a transformer-based model."
- You can transform GPT-1/2 into DeepSeek V3.2 architecture with "a few lines of code." It's the same scaffold.
- MoE: "almost everyone has an MoE now." DeepSeek V3 restarted the trend in Dec 2024; Kimi scaled DeepSeek architecture from 670B → 1T parameters; Mistral 3 adopted DeepSeek V3 architecture directly.
- DeepSeek V3.2: added multi-head latent attention + sparse attention on top of MoE.
- GPT-4.5 failure mode: rumored to be bigger GPT-4, "too big, too expensive, abandoned, went different direction with GPT-5." Lesson: bigger architecture alone is not the answer.
- World models for code (Meta paper): added objective during training to predict internal variable states at each iteration ("if someone steps through this code, this variable has value X"). Forces model to "understand" rather than just predict next token. Expensive but potentially pushes state-of-the-art.
- Recursive/hierarchical models: transformer variant that recurses — writes intermediate answer, model looks at it, takes another round. Cheap model, expensive inference. "Very specific to a particular task — each model handles one task, not all three things. Hard to compare to Gemini/GPT."

### Post-training timeline (Raschka's periodization)

- 2022: RLHF → ChatGPT + PPO
- 2023: LoRA + SFT
- 2024: Mid-training (continued pre-training on curated data)
- 2025: RLVR + GRPO

### RLVR mechanics (from transcript)

- RLHF required: multiple outputs → humans rank → train reward LLM → train value LLM → PPO loop. 3 models in memory: policy + reward model + value model. "For 600B parameters, you have three times 600B in memory. Very expensive."
- RLVR + GRPO: replace reward model with verifiable checker (math parser, code compiler), replace value model with group-relative normalization. One model in memory.
- GRPO = Group Relative Policy Optimization. "The R stands for 'relative' — you compare completions relative to each other."
- "You can take a base model, skip SFT and RLHF entirely, just do RLVR and get a really good reasoning model. But it's recommended to do SFT+RLHF first."
- 50 RLVR steps on Qwen 3: 5% → 50% accuracy on MATH-500. "It's not learning new math knowledge. It's unlocking knowledge that's already in the pre-training."
- "Whether the reasoning behavior comes from pre-training data or RLVR: a bit of both. A lot of pre-training data already has chain-of-thought format — math textbooks, code comments with explanations."

### PRM discussion

- DeepSeek-R1 "unsuccessful attempts" paragraph: tried PRM, found reward hacking when a grader model assesses intermediate steps. Grader unreliable, not worth it.
- DeepSeek-Math v2: 3-model chain (generator + step-grader + meta-grader). Gold-level math benchmark performance. "It's expensive but adds usefulness."
- "We will see process rewards as standard repertoire at some point. It's just tricky right now."

### Hybrid thinking mode / `<think>` tokens

- Qwen 3 supports "thinking mode" vs "non-thinking mode." Empty `<think></think>` tokens → model skips reasoning chain → faster, cheaper. Populated → full CoT.
- During RLVR training you can add a format reward for adherence to thinking token structure. This introduces a second reward signal alongside accuracy → GRPO instability with two rewards.
- GDPO (NVIDIA, 2025): algorithmic improvement specifically for multi-reward GRPO stabilization.

### GRPO stability issues (practitioner notes)

- Vanilla GRPO: instability every few hundred to thousand steps. "The model works fine, then suddenly really bad. You roll back to the previous checkpoint."
- Community tips: drop KL divergence term for math (performs better), drop standard deviation normalization when all rewards are identical (skip update entirely).
- "It's like Adam vs SGD vs RMSprop — all converged to AdamW by adding tricks. GRPO is at that stage now."

### Inference scaling (detailed)

- "Inference scaling" includes: (a) reasoning models generating more tokens (sequential), (b) parallel sampling / Best-of-N, (c) judge-model-selected sampling, (d) self-refinement loops, (e) decomposed prompting (RLMs paper: LM splits prompt into sub-prompts, runs recursively).
- OpenAI Oct 2024 chart: training scaling and inference scaling both trend upward with similar slope. "You can invest more money at training (one-time) or at inference (per-query)."
- Reasoning models break the clean train/inference cost separation: more tokens at inference → more cost regardless of training investment.
- Tool calling benchmark: GPT-OSS release showed ~1.2× performance uplift from enabling tool calling on identical weights. "Not 2× but definitely a jump."
- Raschka hypothesis: "ChatGPT feels better than locally-run DeepSeek not just because of model quality, but because OpenAI does prompt cleaning, context management, history handling — engineering that isn't in the weights."

### Benchmaxing and evaluation

- "Benchmaxing" (2025 neologism): training to exploit leaderboard metrics; leaderboards reward style (well-formatted wrong answers) over correctness (expert verification required).
- Llama 4 rumored to have separate model for benchmarks.
- "Even if they're all benchmaxing, the ranking is still consistent. So it cancels out. But benchmarks are saturated and hard to use as a signal."
- Raschka: "I stopped looking at benchmark numbers. I just use the model."
- Future metrics: agentic benchmarks — "how long can the model run to solve a complex objective" — not one-shot Q&A.

### Continual learning

- Hot topic at NeurIPS 2025 but no technical breakthrough.
- Practical limitation: model hosted in datacenter on 600B+ parameters — you can't update it like a small fine-tune. Catastrophic forgetting. Risk of garbage data entering training loop.
- What companies actually do: "controlled continual learning" — collect failure cases, curate a dataset, do controlled re-training. Reflected in rapid model versioning: GPT-4 → 4.1 → 4.5 → 5 → 5.1 → 5.2 etc.
- Raschka: "2027 maybe, but even that is ambitious."

### Meta-lesson for framework builders

- "There's no magic bullet. It's a lot of little tips and tricks all over the place. Pre-training team, post-training team, architecture team, inference team — all working simultaneously on separate improvements that compound."
- "Benchmarks measure the wrong thing. The progress is real but it's felt, not measured."

## Don't Teach. Incentivize. (Hyung Won Chung, OpenAI) — https://www.youtube.com/watch?v=kYWUEV_e2ss — transcribed

*MIT talk; Chung is Research Scientist at OpenAI, formerly Google Brain; known for Flan, Flan-T5, Flan-PaLM, T5X*

### Core Thesis

- "It's impossible to enumerate everything we want to teach a model. The only feasible way to get to general intelligence is to weakly incentivize the model so that the models themselves figure it out."
- This is not a technical talk about a specific paper — it's a philosophy/perspective talk on *how to find the right problems to solve in AI*.

### The Bitter Lesson (Rich Sutton) as Foundation

- Chung considers Rich Sutton's keynote chart (compute per $1,000 from 1900–2020, log scale) "the most important data points I know in the entire AI field."
- Compute cost falls exponentially over ~100 years. "I don't know any other trend that is as strong and as long-lasting."
- Conclusion: "I should not compete with this. I want to leverage this as much as possible in every aspect of my career."
- Bitter lesson: "Progress in AI over the past 70 years essentially boils down to developing progressively more general methods with less structure and adding more data and compute." — Chung: "I think this is the single most important writing in AI."

### Scaling Redefined (Chung's version)

- Common definition of scaling: "doing the same things with more machines." Chung's version: "identifying the modeling assumption or inductive bias that bottlenecks further scaling and replacing it with a more scalable one."
- Example: SVM vs deep learning — data representation was the bottleneck in SVM; deep learning replaced it with learned representations. That transition IS scaling in Chung's framework.
- Pattern: more structured methods start fast (structure = shortcut), hit a ceiling; less structured methods start slow (too much freedom), eventually surpass as compute grows. "We call this more scalable."
- Human analogy: chess engine α-β pruning (structured, handcrafted) vs learned policy. "Whatever the model learns for winning might be different from what humans think of as good chess — but I don't think human intelligence is any form of upper bound."

### Why Clever Structures Become Bottlenecks

- "Clever structures posed by human researchers typically become the bottleneck when scaled up."
- "What is good in the long run almost necessarily looks bad in the short term" — because we're doing learning-based methods and giving machines as much freedom as possible.
- "Computer is getting cheaper faster than we're becoming better researchers. So we should not compete with that. Instead, give machines more degrees of freedom and let them choose how they learn."
- Researchers resist this because "just scaling up is not scientific or interesting" — Chung's rebuttal: "Why are we doing AI at all? To create value that benefits humanity. That is more important than any ego of the scientist."

### Next Token Prediction as a Weak Incentive Structure

- LLMs are a sequence-to-sequence Transformer: input = N vectors of size d; interaction modeled as dot products between token vectors; output = next token probability distribution over vocabulary (e.g., 100K items).
- "We don't directly teach any linguistic concepts — verb, noun, etc. We just predict next tokens. Language just emerges. That's almost a byproduct."
- "I would go further: next token prediction is the best way to teach language precisely because we don't put any structure into it."
- The "language model" label is a misnomer: "We're not teaching language. Language is one representation of deeper knowledge."
- Massive implicit multitask learning hypothesis: at web scale (trillions of sentences), each requiring a different skill, it becomes intractable for a model to memorize task-by-task. The economical solution: learn general skills (language syntax, semantic understanding, reasoning) that transfer across tasks.
- "These abilities emerge and are typically more General because they're driven by the need to develop general skills."
- Observable proof: PaLM paper — just predicting the next token achieves better-than-human-average on many Big Bench tasks without any explicit teaching of those tasks.

### Incentive Structure for Hallucination — the Concrete Reward Table

- Explicit signal: model answers questions correctly.
- Induced incentive: model must learn what it knows and doesn't know, because it can't memorize trillions of Q&A pairs.
- Proposed reward structure for hallucination (from a Sean Carroll talk Chung adapted):
  - +1.0: correct AND unhedged answer ("The answer is X")
  - +0.5: correct but hedged ("I'm not sure, but maybe X")
  - 0.0: "I don't know" response
  - -2.0: incorrect AND hedged ("Maybe X, though I'm unsure")
  - -4.0: incorrect AND confident ("The answer is definitely X")
- With trillions of questions under this reward structure, the induced incentive is for the model to learn the general notion of "knowing vs not knowing" rather than memorizing which specific questions it knows.
- "That ability is what might emerge out of this induced incentive structure. That is the only fundamental way to solve hallucination."

### Generalist vs Specialist Trade-off (doesn't exist for machines)

- Humans face a time-budget trade-off: time spent as generalist = time NOT spent as specialist.
- Machines don't face this: one model can enjoy far more compute than another. The "multiplier" isn't 365× (Hyperbolic Time Chamber analogy); it's orders of magnitude higher.
- "I don't think this trade-off exists at all for machines. If anything, generalists are actually better at specialized things."
- Implication: small specialist models defeating large generalist models is a human bias. The right framing is "which model gets more compute," and generalists usually win at scale.

### Threshold Intelligence Prerequisite

- "No amount of bananas can incentivize monkeys to do mathematical reasoning."
- Incentive structures only work above a capability threshold. "Currently with something like GPT-4, we cross that threshold for many, many tasks." This is why incentive-based RL is now viable in ways it wasn't with earlier models.
- What abilities emerge depends on model scale: "If the model is too small, it might just give up on developing general skills and settle for simple heuristics."

### Emergence and Unlearning

- "Things that don't work now don't mean they won't work later." Key rule: replace "this doesn't work" with "this doesn't work *yet*."
- AI research is unlike physics: the underlying "axioms" (the most capable model) change every couple of years. Every new foundation model is a "different planet with different physics."
- "GPT-3 came out in 2020 — that was the axom researchers built intuitions on. GPT-4 changed everything. Many things built on top of GPT-3 intuitions are no longer relevant."
- Constant unlearning required: "Researchers who come in with not much knowledge might think of themselves as having not much baggage to unlearn — and they're more flexible."
- "Many people at OpenAI are not traditional ML PhDs. When they see evidence change, they adopt a new paradigm."

### Closing Summary (Chung's own words)

- "The most important underlying driving force: compute cost is decreasing exponentially. AI researcher's job, recognizing this, is to not compete with that and just leverage it by designing more scalable methods."
- "Current generation of language models relies on next token prediction, which can be thought of as a weak incentive structure that needs to learn general skills to handle trillions of task types."
- "We should start thinking: next token prediction has been great, but it's not the only thing. We should really think about incentive structures for models. That's the new learning paradigm we should engage in."
- "Emerging abilities happen. We need the right perspective: unlearn things based on outdated axioms."

## → Verso Implications

### 1. Do NOT over-scaffold reasoning — it is the single most load-bearing implication

- RLVR's core result: 50 RL steps on Qwen 3 goes from 5% → 50% MATH accuracy. The model already had the reasoning knowledge in its weights; the scaffold just unlocked it. Verso must treat modern LLMs (especially reasoning models like o3, o4-mini, Claude 3.7, Qwen 3) as reasoning-capable primitives, not as dumb function callers that need elaborate scaffolding to think.
- **Concrete rule**: if Verso is calling a reasoning-capable model, do NOT chain multiple "let me break this down" prompts, do NOT inject intermediate verification steps, do NOT wrap in a multi-agent "planner → executor → verifier" graph by default. Give the model a clear problem and a verifiable exit condition. Let it reason.
- Exception: use scaffolding only when you have a *verifiable* multi-step problem where intermediate steps can be checked (code execution, math verification) — i.e., exactly when RLVR applies.

### 2. Tools over chain-of-thought for grounding

- Raschka: tool calling gives ~1.2× benchmark uplift on same model weights; reduces hallucinations because model outsources factual lookups rather than remembering. Chung: next token prediction produces hallucinations because it lacks a "what I don't know" representation at the right scale.
- Verso's tool system (MCP-first, first-class tools) is the architecturally correct response to both findings. A tool call to a search engine or code executor is a *verifiable reward* in real-time — exactly what RLVR trains models to exploit.
- **Concrete rule**: Verso's first-class tools should include at minimum: code executor (verifiable), web search (grounded), file system (persistent state). These aren't convenience — they are the mechanisms that replace both hallucination and over-scaffolding.

### 3. GRPO instability informs Verso's eval loop design

- Vanilla GRPO is "flaky": models collapse to bad states every hundreds-to-thousands of steps. The community fix: checkpoint more frequently, roll back on collapse, combine multiple reward signals carefully.
- Verso's evals module should think the same way: don't rely on a single aggregate score; track multiple reward signals (task success, format adherence, latency, tool use accuracy); support checkpoint/rollback of agent configurations; flag when eval scores suddenly drop (the GRPO collapse signal).
- **Concrete rule**: Verso's eval framework should support multi-signal reward composition (not a single score) and anomaly detection on score trajectories — not just "did it pass or fail."

### 4. Verifiable rewards as the design principle for agent evals

- RLVR's power comes from having a deterministic verifier (math parser, code compiler). The moment you replace the verifier with "LLM judge," you get reward hacking. DeepSeek tried PRM (LLM grading intermediate steps) and called it an "unsuccessful attempt."
- **Concrete rule for Verso evals**: wherever possible, build evals against deterministic verifiers — code that runs correctly, API calls that return expected schema, outputs that parse to valid types. LLM-as-judge evals should be explicitly labeled as "soft evals" and not used as primary optimization targets.
- The DeepSeek-Math v2 3-model chain (generator + grader + meta-grader) is a usable pattern for Verso's internal quality loop, but only when the meta-grader has a verifiable signal at the top.

### 5. Hybrid thinking mode → Verso should expose reasoning budget as a first-class control

- Qwen 3's empty `<think>` tokens turn off reasoning; populated ones run full CoT. This is user-accessible compute cost control.
- **Concrete API design for Verso**: expose a `reasoning_effort` or `thinking_budget` parameter at the agent level (not hidden inside a system prompt). Allow callers to say: this task is a simple lookup (skip reasoning), this task is a complex plan (full reasoning). This maps directly to how frontier models work and lets Verso route cost-effectively.
- This also prevents the anti-pattern of always running reasoning models at full compute on simple subtasks.

### 6. Inference-time scaling patterns Verso should support natively

- Best-of-N sampling: Verso's agent should support running N completions and selecting via verifiable scoring — already a core RLVR pattern and directly applicable to any agentic task with a verifiable exit condition.
- Self-refinement loop: optional, opt-in, with a hard max-iterations limit and a verifiable improvement signal (not "does it look better" but "did the score go up").
- Recursive decomposition (RLMs): Verso's task decomposition primitive should allow the model to self-decompose a prompt into sub-tasks rather than having the framework hard-code decomposition trees. This is the "less structure, more scalable" principle applied to orchestration.

### 7. The Bitter Lesson applied to Verso's architecture philosophy

- Chung's definition of scaling: "identify the modeling assumption or inductive bias that bottlenecks further scaling and replace it with a more scalable one." Applied to agent frameworks: the bottleneck is hand-crafted orchestration graphs (explicit planners, rigid state machines, hardcoded tool sequences). These are the SVM of the agent world.
- The scalable alternative: a minimal ReAct loop with first-class tools and a verifiable reward signal. This is exactly Verso's thesis. Chung provides the theoretical justification: structured methods start fast, hit a ceiling; unstructured (model-driven) methods eventually dominate as the models get better.
- **Warning**: LangGraph-style explicit graphs are the "more structured" approach that provides early wins but will be a ceiling. Verso's escape hatch for graphs should be opt-in for the specific legitimate cases (durable execution, HITL checkpoints) — never the default.

### 8. RLVR scope expansion → Verso's tool registry will expand accordingly

- RLVR is expanding beyond math/code to citation-checking, medical verification, etc. Every new verifiable domain = new type of tool that agents can use with a built-in accuracy signal.
- **Concrete rule**: design Verso's tool interface so that tools can optionally return a verification signal alongside their output. A tool that returns `{"output": "...", "verified": true, "confidence": 0.95}` enables the agent loop to natively score tool-use quality without a separate judge model.

### 9. Benchmark saturation → Verso needs domain-specific evals, not generic benchmarks

- Raschka abandoned benchmark numbers entirely ("I just use the model and see if it's better"). Agentic benchmarks that measure "how long can it run on a complex objective" are more informative than one-shot Q&A scores.
- **Concrete rule**: Verso's eval library should ship with agentic-length benchmarks (multi-step task completion, recovery from errors, cost efficiency over a task trajectory) rather than just accuracy-on-a-dataset metrics. These are what correlate with real-world value.

### 10. Threshold intelligence → routing matters

- Chung: incentive structures only work above a capability threshold. Small models below threshold "give up and settle for simple heuristics."
- **Concrete rule for Verso's model routing**: do not send reasoning-intensive tasks to sub-threshold models. Verso should have an explicit model tier system: (a) reasoning-capable (o3, o4-mini, Claude 3.7, Qwen 3 QwQ) for tasks requiring self-directed reasoning, (b) fast/cheap (GPT-4o-mini, Claude Haiku) for tool-dispatch and simple lookup tasks. Mix by task type, not by cost alone.
