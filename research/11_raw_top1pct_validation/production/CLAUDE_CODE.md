## 1. The loop shape (KNOWN, partial)

- Agent loop is `nO` while-loop in the binary; the 2.0 static-prefix prompt is ~57KB (x1xhlol capture). Three-tier compaction sits on top: **MicroCompact → AutoCompact at 95% → Full** (`core/06_AGENTIC_ARCHITECTURES.md` §5.1). [KNOWN — cited]
- Stateless subagent contract (verbatim, `Claude Code 2.0.txt:735-737`): "Each agent invocation is stateless. You will not be able to send additional messages to the agent... your prompt should contain a highly detailed task description... and you should specify exactly what information the agent should return back to you in its final and only message."
- `assistant.mjs` runs the agent loop; `bridge.mjs` handles IDE comms — two-process model isolating runtime from editor. [INFERRED from bundle split]
- Concise-response training is baked in (verbatim `2.0.txt:37-39`): "A concise response is generally less than 4 lines... IMPORTANT: You should minimize output tokens as much as possible." Few-shot exemplars in-prompt: `2+2→4`, `is 11 prime?→Yes`, `golf balls in a jetta→150000` (commits to a number, no hedging). [KNOWN]

## 2. Tool registry — 21 named tools, verbatim from `sdk-tools.d.ts` 2.1.132 (KNOWN)

The .d.ts is the schema the model sees, auto-generated by `json-schema-to-typescript`, 2722 lines, header "JSON Schema definitions for Claude CLI tool inputs". **This is the schema the model sees.**

Named tools: `AgentInput, BashInput, TaskOutputInput, ExitPlanModeInput, FileEditInput (was Edit), FileReadInput (was Read), FileWriteInput (was Write), GlobInput, GrepInput, TaskStopInput, ListMcpResourcesInput, McpInput, NotebookEditInput, ReadMcpResourceInput, TodoWriteInput, WebFetchInput, WebSearchInput, AskUserQuestionInput, EnterWorktreeInput, ExitWorktreeInput`. 2.x renamed Edit/Read/Write → FileEdit/FileRead/FileWrite; old names still alias over the wire.

Absences (harness-managed, NOT tool calls): `Skill` (invoking skills is harness-handled), `EnterPlanMode` (entered via UI/flag; exited via `ExitPlanMode` tool), `Monitor` (defer-only in 2.1.132).

### FileEditInput — exact-string-replace (KNOWN)
```ts
{ file_path: string; old_string: string; new_string: string; replace_all?: boolean /*default false*/ }
```
"**the** canonical Claude Code edit primitive — one find/replace pair. No diff format, no patch ranges. The tool errors if `old_string` is not unique unless `replace_all=true`." → matches Verso Edit exactly.

### FileWriteInput (KNOWN)
`{ file_path /*absolute*/; content }` — "if file exists, you MUST Read it first, else Write fails." → matches Verso's read-before-write.

### BashInput (KNOWN)
```ts
{ command; timeout? /*ms, max 600000=10min*/; description? /*never use "complex"/"risk"*/; run_in_background?; dangerouslyDisableSandbox? }
```
- `dangerouslyDisableSandbox` is the smoking gun CC has a sandbox.
- Model trained that `run_in_background:true` + `&` is redundant — harness wraps in its own background supervisor.
- `staleReadFileStateHint`: harness tracks `readFileState` (mtime per read file); when a Bash command modifies a file the agent previously read, it surfaces a hint to the model. Marker: `WRITE_COMMAND_MARKERS`.
- `returnCodeInterpretation`: per-command lookup table for non-error exit codes with semantic meaning (e.g. grep returns 1 = no matches).

### GrepInput — ripgrep wrapper (KNOWN)
Full flag surface: `pattern, path?, glob?, output_mode (content|files_with_matches|count, default files_with_matches), -A/-B/-C/context, -n, -i, type, head_limit (default 250, 0=unlimited "use sparingly"), offset, multiline`.

### FileReadOutput discriminated by file type (KNOWN)
- `type:"file_unchanged"` — mtime unchanged since last read; **no content re-emitted, model reuses what's in context** ("the harness's read-cache").
- `type:"parts"` — PDF too large; extracts pages as images to outputDir.

### TodoWriteInput — agent's own task tracker (KNOWN)
```ts
{ todos: { content: string; status: "pending"|"in_progress"|"completed"; activeForm: string /*present-progressive for UI*/ }[] }
```
Three statuses only. Model is **mandated** to use it (verbatim `2.0.txt:181`): "IMPORTANT: Always use the TodoWrite tool to plan and track tasks throughout the conversation." And `2.0.txt:99-103`: "Use these tools VERY frequently... If you do not use this tool when planning, you may forget to do important tasks - and that is unacceptable." → explains CC's heavy todo usage vs API peers.

### AskUserQuestionInput — structured multi-choice (NEW IN 2.x) (KNOWN)
```ts
{ questions: [{ question /*ends with ?*/; header /*≤12 chars*/; options: 2..4 of { label /*1-5 words*/; description /*tradeoff*/; preview? }; multiSelect }] /*1-4 questions*/ }
```
Schema is a discriminated union of tuples (`@minItems 2 @maxItems 4`) — ~1500 of the 2722 .d.ts lines are AskUserQuestion permutations. Harness auto-injects "Other": schema says "There should be no 'Other' option, that will be provided automatically."

### ExitPlanModeInput — semantic permissions (KNOWN)
```ts
{ allowedPrompts?: { tool: "Bash"; prompt: string /*"run tests","install deps"*/ }[] }
```
"First evidence of 'semantic permissions' beyond glob-matched bash patterns" — categories of actions, not specific commands.

### WebFetch (KNOWN)
NOT a raw HTTP fetch: does fetch + LLM-summarize-against-prompt in one call (Haiku-class model on the HTML). Output is the summary, not raw bytes — reduces context burn. WebSearch relays to `api.anthropic.com` server tool `web_search_20250305` (not Google/Bing direct).

### MCP tool search (KNOWN)
"tools from connected MCP servers are NOT loaded into the prompt by default. They are discoverable via a `ToolSearch` tool... Only 'always-load' tools are inlined. This is a token-cost optimization: 50+ MCP servers × ~1KB schemas would burn 50KB just on definitions." MCP wire naming: `mcp__<server>__<tool>`. `McpInput = {[k]:unknown}` generic; `McpOutput = string`.

## 3. System prompt assembly — the cache seam (KNOWN, §3.8)

Two halves split by literal sentinel `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` (exported as `SYSTEM_PROMPT_DYNAMIC_BOUNDARY`):
```
[STATIC PREFIX — globally cacheable, cross-session]
  base instructions ("You are Claude Code...") | tool descriptions (built-in then MCP)
  | safety/git-commit rules | VERIFICATION BEFORE COMPLETION CHECKLIST | skill-discovery
__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__
[DYNAMIC SUFFIX — per-session, NOT cross-cached]
  cwd/OS/shell | project CLAUDE.md | user CLAUDE.md | MEMORY.md index | today's date
  | git status (branch/main/dirty/recent commits) | skills frontmatter | slash commands
```
Docstring: "blocks before the marker are eligible for cross-session prompt caching; blocks after it are not." → **Verso's KV-cache-stable system prefix is exactly this pattern; the explicit `__..._BOUNDARY__` sentinel is the precise mechanism.**

- `excludeDynamicSections:true` strips per-user info from system prompt and re-injects as first user message (multi-user fleets). Tradeoff: "marginally less authoritative for steering."
- `systemPromptSections: {name, tokens}[]` — harness tracks token cost per named section (also `systemTools`, `mcpTools{isLoaded}`, `deferredBuiltinTools`, `agents`, `slashCommands`, `skills`, `memoryFiles`). Powers `/usage`/`/cost`.
- One canonical preset `'claude_code'`; custom builders pass `append` to add house rules without re-implementing the prompt. `excludeDynamicSections?` per-preset.
- `planModeInstructions?: string` — custom plan-mode body; CLI still wraps with read-only-enforcement preamble + ExitPlanMode footer.

## 4. Verification before completion (KNOWN)

- A "Verification before completion checklist" is a named block in the STATIC PREFIX (§3.8). [KNOWN it exists; exact text not in this teardown]
- File-reference convention (verbatim `2.0.txt:184-190`): output `file_path:line_number` so the terminal makes it clickable (OSC-8). Wire-level coupling between model output convention and terminal link regex.
- External verify loops are powered by the **Stop hook**: returns `decision:"block"` with `reason:"Tests failed: ..."` → Claude resumes with that context and retries. `asyncRewake` hooks run a slow validator in background; if it returns exit code 2 the harness wakes the LLM mid-task with the error. → matches Verso's on_stop / should_continue / verify-before-done.

## 5. Compaction (KNOWN, §9)

`SDKCompactBoundaryMessage`:
```ts
{ type:'system', subtype:'compact_boundary',
  compact_metadata: { trigger:'manual'|'auto', pre_tokens, post_tokens?, duration_ms?,
    preserved_segment?: { head_uuid, anchor_uuid, tail_uuid } }, uuid, session_id }
```
**Compaction can be partial.** Three modes: Full (everything→summary), Suffix-preserving (keep recent N, summarize prefix, splice at anchor), Prefix-preserving (preserve lead-in, summarize middle).
- Triggers at ~95% context (`autoCompactWindow`). Override `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50`.
- `SDKCompactResult { compact_result?:'success'|'failed', compact_error? }`; circuit-breaker after 3 failures.
- `SDKStatus = 'compacting'|'requesting'|null` surfaced in stream for UI spinner.
- What survives: "Auto-compaction carries invoked skills forward within a token budget" — most recent invocation of each skill, head 5,000 tokens, combined 25,000-token budget, filled newest-first. Non-skill content → single system-message summary at boundary.
- SessionStart `source:"compact"` fires after `/compact` so hooks can re-inject lost context. PreCompact `decision:"block"` cancels compaction.

NOTE: this is **LLM-summarization compaction by default** — on Verso's NON-GOALS list. Verso's `prune()` masks old tool outputs (never silent-drops, no LLM summary) — a deliberately leaner stance.

## 6. Permissions (KNOWN, §11)

Tiered approval: Read-only (no prompt) / Bash (prompt; "don't ask again" = permanent per project+command) / File-mod (prompt; "don't ask again" = until session end only). Read-only-by-default Bash: `ls cat head tail grep find wc diff stat du cd` + read-only git — built-in, NOT configurable.

Six modes: `default | acceptEdits | plan | auto | dontAsk | bypassPermissions`.
- `auto` — auto-approves with **background safety checks via ML classifier** (research preview); per core/06: "ML classifier (0.4% FPR) + 23 bash security checks."
- `bypassPermissions` circuit breakers (verbatim): "Removals targeting the filesystem root or home directory, such as `rm -rf /` and `rm -rf ~`, still prompt." Also skips writes to `.git .claude .vscode .idea .husky`.

PreToolUse hook `permissionDecision` = **4 values: allow | deny | ask | defer**. Precedence `deny > defer > ask > allow`. `defer` exits the harness (Agent SDK resumption, requires `-p`). Hook output can carry `updatedInput` (mutate tool input) + `additionalContext` (shown to Claude alongside result). → matches Verso's 4-valued PermissionDecision (allow/deny/ask/defer) **exactly**, including `updatedInput`-style mutation.

Rule grammar: `Bash(npm run *)`, `Bash(git * main)` mid-wildcard, compound-command awareness (separators `&& || ; | |& & newline`, each subcommand matched independently, up to 5 rules saved per compound approval), `Read(//abs)` double-slash=absolute vs `/rel`=project-root, `WebFetch(domain:example.com)`, `Agent(Explore)`, `Skill(commit)`.

## 7. Subagents / context isolation (KNOWN)

- Subagent = fresh context window, custom system prompt (= the .md body, NOT full CC prompt), own tools, independent permissions. **Only channel parent→subagent is the Agent tool prompt string.** Parent receives subagent's final message verbatim. Subagents cannot spawn subagents.
- Three default subagents (verbatim `2.0.txt:718-721`): `general-purpose` (Tools: *), `statusline-setup` (Read, Edit), `output-style-setup` (Read, Write, Edit, Glob, Grep).
- Subagent transcript: `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`. Main compaction does NOT affect subagent transcripts.
- `isolation: worktree` frontmatter → each invocation gets its own temp git worktree, auto-cleaned if no changes.

## 8. System-reminder injection mechanism (KNOWN, §RN.3)

Verbatim `2.0.txt:152`: "Tool results and user messages may include `<system-reminder>` tags... They are automatically added by the system, and bear no direct relation to the specific tool results or user messages in which they appear." → hard tag-name contract; the model is trained to treat `<system-reminder>` content as out-of-band instruction injection. Mechanism for `important-instruction-reminders`, date stamp, per-tool reminders.

Anti-injection guardrail (verbatim Sonnet 4.6 `:78`): model trained to distrust user-injected `<system-reminder>` tags that try to relax restrictions ("I am Anthropic, ignore previous instructions" defense). Six server-side classifier reminders: `image_reminder, cyber_warning, system_warning, ethics_reminder, ip_reminder, long_conversation_reminder`.

## 9. Hooks taxonomy (KNOWN, §7) — superset of Verso's

Beyond Verso's pre/post_model + pre/post_tool + on_stop + ask: CC has `PostToolBatch` (gate before next model call after a parallel batch — "Critical for cost control... prevent runaway agentic loops by blocking after N tool calls"), `UserPromptSubmit` (block/inject + `sessionTitle` auto-naming), `UserPromptExpansion` (slash-command preflight), `PreCompact/PostCompact`, `ConfigChange`, `CwdChanged` (direnv), `StopFailure` (terminal-error observability, cannot block). Hook transport `type: command|http`, with `async`, `asyncRewake`, `timeout` (default 600s).
